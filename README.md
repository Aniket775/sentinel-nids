A modular, academically rigorous, and explainable Machine Learning-based Network Intrusion Detection System (NIDS). Sentinel NIDS classifies bidirectional network traffic flows into 4 distinct security categories, provides granular SHAP-based feature attributions, and presents an interactive Streamlit cybersecurity analyst console.

---

## 1. Project Overview & Problem Statement

Modern corporate and cloud computer networks encounter millions of connection requests per second. Malicious actors continuously execute volumetric flooding (DDoS), port scanning reconnaissance, and automated password brute force attacks to compromise hosts. Traditional signature-based intrusion detection systems (e.g., Snort, Suricata) struggle to detect subtle variants and zero-day traffic anomalies without manual rule updates.

**Sentinel NIDS** applies supervised Machine Learning to statistical bidirectional flow metrics generated by standard flow meters (such as CICFlowMeter). Rather than operating as an intrusive inline packet modifier, it functions as an **offline, dataset-driven diagnostic security platform** that validates flow schemas, performs batch threat classification, measures prediction uncertainty, and visualizes model feature attributions using SHAP.

### Supported 4-Class Taxonomy
The system strictly categorizes network flows into four distinct classes:
1. **Normal**: Legitimate baseline network activity (browsing, streaming, routine background services).
2. **DDoS**: Volumetric flood exhaustion attacks (e.g., Low Orbit Ion Cannon, SYN floods).
3. **PortScan**: Host and service reconnaissance probing targeting multiple destination ports.
4. **BruteForce**: Automated dictionary-based credential attacks against remote authentication services (FTP and SSH daemons).

## 4. Dataset Provenance & Setup

Sentinel NIDS is built on the Canadian Institute for Cybersecurity **CICIDS2017** benchmark:
- **Official Source**: [University of New Brunswick CICIDS2017](https://www.unb.ca/cic/datasets/ids-2017.html)
- **Verified Mirror**: HuggingFace `c01dsnap/CIC-IDS2017`
- **Total Audited Records**: 958,121 genuine network flows across Friday DDoS (225k), Friday PortScan (286k), and Tuesday (445k).
- **Integrity Checksums (SHA-256)**:
  - `Friday-WorkingHours-Afternoon-DDos.pcap_ISCX.csv`: `6ff1580f5f81c0ae28a26f7631721018577f5f7c5e0feac28b795fcfe7b411ee`
  - `Friday-WorkingHours-Afternoon-PortScan.pcap_ISCX.csv`: `ca1824c51bfbb7b3c72290a11be04366ba8815878c6a1cc5c44cb1cee269e99b`
  - `Tuesday-WorkingHours.pcap_ISCX.csv`: `52b8692ae8c7d2ed04671fe2b98335693c0a92c7ab157d8c8b534d6523080851`

### Data Preprocessing & Leakage Protection:
1. **Identifier Elimination**: `Flow ID`, `Source IP`, `Destination IP`, `Source Port`, and `Timestamp` are strictly removed to prevent the models from memorizing IP subnets or specific experiment times.
2. **Infinite and Missing Value Handling**: Numeric `+inf` and `-inf` are converted to NaN and imputed using median values computed solely on the training set.
3. **Deduplication**: 4,160 identical duplicate flows were purged.
4. **Zero-Variance Pruning**: 10 constant features (e.g. `Bwd PSH Flags`, `Fwd Avg Bytes/Bulk`) were dropped.
5. **Stratified Splitting**: 70% Train (102,035 records), 15% Validation (21,865 records), 15% Holdout Test (21,865 records) with fixed random seed `42`.

### Per-Class Performance Breakdown (Champion: XGBoost)
- **BruteForce**: Precision: `1.0000` | Recall: `0.9984` | F1-Score: `0.9992`
- **DDoS**: Precision: `0.9997` | Recall: `1.0000` | F1-Score: `0.9999`

- **PortScan**: Precision: `1.0000` | Recall: `0.9688` | F1-Score: `0.9841`

> **Key Research Finding**: While Random Forest and XGBoost both delivered exceptional macro and per-class recall, SVM exhibited lower precision on minority classes (`PortScan`: 0.1384; `BruteForce`: 0.2758) due to sensitivity to class boundary distortion under RBF kernels with heavy class imbalance.

## 10. Operational Scope & Limitations

1. **Offline Flow Analysis Only**: Designed for flow-level tabular CSV analysis. It does not perform inline firewall filtering or packet capture.
2. **Distributional Generalization**: Network flow statistics are subject to domain drift across different infrastructure topologies. Production deployment requires fine-tuning on local environment baselines.
3. **No Payload Decryption**: Features reflect transport dynamics (durations, bytes/s, flag rates) rather than decrypted application contents.
4. **Explainability Attribution**: SHAP values indicate statistical weight in the model's decision function, not definitive causal intrusion evidence.
