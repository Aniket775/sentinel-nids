## 1. Introduction
With the exponential expansion of cloud infrastructures, IoT networks, and distributed enterprise architectures, computer systems face relentless attacks from sophisticated threat actors. Defending network perimeters demands automated, high-throughput systems capable of analyzing millions of connection flows. Traditional signature-based Intrusion Detection Systems (IDS) rely on deterministic pattern matching rules (e.g., matching byte sequences with known malware payloads). However, they fail to generalize to zero-day attacks, modified payloads, or high-volume volumetric anomalies.

This project delivers **Sentinel NIDS**, a complete, professionally engineered, and explainable offline Network Intrusion Detection System powered by machine learning algorithms (Random Forest, Support Vector Machines, and XGBoost) and explainable AI (SHAP).

---

## 2. Problem Statement
Network traffic data possesses unique characteristics that present severe hurdles for machine learning models:
1. **Extreme Class Imbalance**: Legitimate (`Normal`) traffic overwhelmingly dominates real-world network traffic (>80–95%), while critical threat vectors (such as password brute force attacks) represent minute fractions of total connections. Models optimized solely for accuracy often learn to predict the majority class, missing severe security breaches.
2. **High Dimensionality and Collinearity**: Flow generators produce over 80 statistical metrics describing flow duration, packet sizes, inter-arrival times, and subflow counters, many of which are collinear or contain zero variance.
3. **Data Leakage Risks**: Naive inclusion of network identifiers such as IP addresses or timestamps causes models to memorize specific experimental subnets or attack schedules rather than generalizable packet dynamics.
4. **Black-Box Opacity**: Cybersecurity analysts cannot act on arbitrary numerical prediction scores without knowing *which* network features triggered the alert.

The core engineering and research objectives achieved in this project include:

5. **Explainable AI Integration**: Implement SHAP (TreeExplainer) to generate global feature attribution plots and localized per-threat explanations.

7. **Interactive Cybersecurity Analyst Dashboard**: Build a dark-themed Streamlit user interface featuring interactive Plotly visualizations, threat filtering, and CSV export.

## 4. Related Approach & Background
Prior research in NIDS has evolved from packet inspection (DPI) to flow-based classification. Flow-based approaches summarize bidirectional packet sequences (defined by 5-tuple: source IP, destination IP, source port, destination port, protocol) into statistical records using tools like CICFlowMeter. 
- **Tree Ensembles (Random Forest)**: Bagging multiple decision trees provides resilience to noisy features and extreme non-linear feature spaces without requiring feature normalization.
- **Support Vector Machines (SVM)**: Constructs optimal hyperplanes in high-dimensional kernel spaces; effective for small sample boundaries, but computationally constrained ($O(N^2)$ to $O(N^3)$) and sensitive to unscaled features and class imbalance.
- **Gradient Boosted Decision Trees (XGBoost)**: Sequentially optimizes weak learners using second-order gradients and histogram-based binning, offering state-of-the-art tabular accuracy and fast inference.
- **SHAP (Shapley Additive Explanations)**: Grounded in cooperative game theory, SHAP fairly allocates the marginal contribution of each network feature to the model's final prediction score.

## 6. Preprocessing & Data Cleaning
The data pipeline (`src/nids/data/cleaning.py`) applies rigorous data hygiene:
1. **Header Whitespace Normalization**: Column names in CICIDS2017 contain erratic leading/trailing spaces (e.g., `' Destination Port'`); all headers are automatically stripped and normalized.
2. **Identifier Stripping**: `Flow ID`, `Source IP`, `Destination IP`, `Source Port`, and `Timestamp` are dropped prior to model fitting to prevent spatial/temporal leakage.
3. **Infinite and Missing Value Imputation**: Flow meters frequently record numeric division-by-zero errors in rate features (e.g., `Flow Bytes/s = inf`). These are converted to NaN and imputed using training-fold medians.
4. **Deduplication**: 4,160 identical duplicate flow records were audited and eliminated.
5. **Zero-Variance Filtering**: 10 constant features with zero variance across all records (e.g., `Bwd PSH Flags`, `Fwd Avg Bytes/Bulk`) were systematically removed.
6. **Class Mapping**:
   - `BENIGN` $\rightarrow$ `Normal` (117,606 records)
   - `DDoS` $\rightarrow$ `DDoS` (23,864 records)
   - `PortScan` $\rightarrow$ `PortScan` (213 records in audited slice)
   - `FTP-Patator`, `SSH-Patator` $\rightarrow$ `BruteForce` (4,082 records)

## 7. Feature Selection Experiment
Feature selection was conducted strictly on the training partition using Random Forest Mean Decrease in Impurity (MDI). From an initial set of 68 cleaned features, the top 25 features were selected:
- **Top 5 Predictive Features**:
  1. `Destination Port`: Captures target service boundaries (e.g., Port 80 for HTTP DDoS, Port 21/22 for FTP/SSH Brute Force).
  2. `Average Packet Size`: Strongly distinguishes volumetric flood bursts from single-probe reconnaissance.
  3. `Fwd Packet Length Mean`: Highlights forward transmission payloads.
  4. `Subflow Fwd Bytes`: Identifies cumulative payload volume per directional flow.
  5. `Avg Fwd Segment Size`: Reflects transport-layer TCP segmentation characteristics.

The feature importance chart was generated and persisted to `reports/figures/feature_importance_ranking.png`.

## 8. Machine Learning Algorithms
Three diverse algorithm families were implemented and compared:
1. **Random Forest Classifier**:
   - 100 estimators, max depth 20, min samples split 5, min samples leaf 2.
   - Handled raw tree inputs with `class_weight="balanced"`.
2. **Support Vector Machine (SVM)**:
   - RBF kernel, $C=1.0$, `gamma='scale'`, `class_weight="balanced"`.
   - Feature inputs normalized using `StandardScaler` fitted solely on training folds.
   - Trained on a documented, representative stratified sample of 25,000 records to bound training time within practical limits.
3. **XGBoost (Histogram GBDT)**:
   - 100 estimators, max depth 6, learning rate 0.1, subsample 0.8, colsample 0.8.
   - Evaluated using multiclass log-loss (`mlogloss`) with histogram binning (`tree_method='hist'`).

---

## 9. Experiment Setup & Protocol
- **Stratified Partitioning**: 70% Training (102,035 records), 15% Validation (21,865 records), 15% Holdout Test (21,865 records).
- **Random Seed**: Fixed globally to `42` across all splits, model seeds, and subsampling.
- **Separation of Concerns**: Preprocessors, scalers, imputers, and feature selectors were fitted strictly on the 70% training fold; the validation and holdout test sets were transformed without refitting.

## 10. Evaluation Metrics
In network intrusion detection, **Macro-F1 Score** and **Per-Class Recall** are the critical primary metrics. Accuracy alone can be dangerously deceptive: a naive model that predicts `Normal` for every record would achieve ~80.7% accuracy on this dataset while completely missing 100% of network attacks.
Metrics calculated:
- Overall Accuracy
- Macro-averaged F1-Score
- Weighted F1-Score
- Macro Precision and Recall
- Per-class Precision, Recall, and F1
- Confusion Matrix (normalized and absolute)
- One-vs-Rest Multiclass ROC-AUC
- Training and Inference Latency

## 12. Error Analysis & Comparative Discussion
1. **Tree-Based Superiority**: Both Random Forest and XGBoost demonstrated near-perfect separation on statistical flow boundaries, achieving Macro-F1 scores above 0.99. Their hierarchical decision splits align naturally with threshold-based network protocol dynamics (e.g. `Destination Port == 22` AND `Flow Duration > 5000ms`).
2. **SVM Minority Class Distortion**: While SVM achieved 89.76% accuracy and high recall (0.9572), its precision for `PortScan` (0.1384) and `BruteForce` (0.2758) was poor. With 1,551 Normal flows misclassified as BruteForce and 193 Normal flows misclassified as PortScan, the RBF decision boundary over-expanded into benign space to satisfy the balanced penalty. Furthermore, SVM inference was ~190x slower than tree-based models due to expensive kernel evaluations across support vectors.
3. **Model Selection**: **XGBoost** was selected as the champion model. It achieved the highest Macro-F1 (0.9958), flawless precision on PortScan and BruteForce (1.0000), lightning-fast training (1.37s), and an inference throughput exceeding 900,000 flows/second.

## 13. Explainability Findings (SHAP)
Using `shap.TreeExplainer` on the selected champion model:
1. **Global Attributions**: Across the evaluation test set, `Destination Port`, `Average Packet Size`, and `Fwd Packet Length Mean` exhibited the highest mean absolute SHAP impact.
2. **Local Threat Attribution**:
   - For a `DDoS` flow: High `Flow Packets/s`, elevated `Average Packet Size`, and destination port `80` contributed massive positive SHAP values toward the DDoS class.
   - For a `BruteForce` flow: Targeted connection to port `21` (FTP) or `22` (SSH), coupled with short flow duration and repeated small forward packet segments, drove high positive attribution toward `BruteForce`.
3. **Interpretability Guardrail**: The system and dashboard explicitly communicate that SHAP scores represent statistical feature importance within the mathematical decision function and must not be conflated with physical causal proof.

## 15. Limitations
1. **Synthetic Testbed Bias**: The CICIDS2017 dataset was generated in an emulated university testbed environment; real-world enterprise traffic may display broader noise and distinct protocol distributions.
2. **Encrypted Payload Blindness**: Flow features represent transport statistical behavior (packet lengths, inter-arrival times, flags). The model does not decrypt application payloads.
3. **Evolving Attack Profiles**: Sophisticated adversaries who deliberately throttle attack rates or randomize packet sizes to mimic normal browsing traffic may evade detection without ongoing model retraining.

## 16. Future Scope
1. **Streaming Flow Ingestion**: Integration with Apache Kafka or RabbitMQ to consume streamed flow meter outputs in near-real-time.
2. **Unsupervised Anomaly Detection**: Incorporating Isolation Forests or Autoencoders alongside supervised classifiers to flag novel zero-day anomalies outside the 4 target classes.
3. **Continuous Retraining & Drift Monitoring**: Implementing automated Population Stability Index (PSI) tracking to detect feature drift and trigger pipeline retraining.
